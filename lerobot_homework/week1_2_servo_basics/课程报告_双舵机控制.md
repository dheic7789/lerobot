# EmbodiedAI 第三周课堂练习报告：两个舵机的串口控制

## 做了什么

按要求不碰 lerobot，只用 pyserial 直接和 SCS215 舵机通信。最后做到：两个舵机编好号，输入两个 0~1 的数字就能同时控制它们，舵机1最大转 90 度，舵机2最大转 45 度。

## 硬件和协议

电脑通过 USB 接驱动板，驱动板再连舵机，波特率 1000000。两个舵机共用一根数据线，发出去的指令两个都能收到，所以必须给每个舵机编号，指令里写几号，就只有几号响应。

## 原理

**1. 编号**
先跑 `set_id.py`，把两个舵机分别编成 1 号、2 号。之后指令里带上编号，总线上只有对应那个会动。

**2. 指令帧**
一帧长这样（大端）：

```
FF FF | 编号 | 长度 | 指令 | 参数(寄存器地址) | 参数 | ... | 校验和
```

比如开 1 号扭矩：

| FF | FF | 01 | 04 | 03 | 28 | 01 | CE |
|---|---|---|---|---|---|---|---|
| 帧头 | 帧头 | ID=1 | 长度=4 | 写指令 | 地址 0x28 | 值=1 | 校验和 |

`0x28 = 40` 是扭矩使能地址，`0x2A = 42` 是目标位置地址。

**3. 校验和**
把除了帧头和校验和本身的字节加起来取反：

```
checksum = (~(编号 + 长度 + 指令 + 参数)) & 0xFF
```

开扭矩那条：1+4+3+40+1=49=0x31，~0x31=0xCE，跟帧尾对得上。

**4. 角度和位置怎么换**
SCS215 位置范围 0~1000，大概对应 0~240 度，所以 1 度 ≈ 4.17 个位置单位。位置用两个字节、高字节在前。比如位置 400 = 0x0190，就是 `01 90`。

**5. 0~1 怎么映射**
题目要的是：范围 90 度、输入 0.5 就到 45 度。直接线性映射：

```
角度 = 输入 × 最大角度
位置 = 起点 + 角度 × 4.17
```

这样舵机1输 0.5 → 45 度，舵机2输 0.5 → 22.5 度，和题目要求一致。

**6. 两个舵机怎么"同时"动**
两个舵机在同一根线上，同一轮里先给 1 号发位置、再给 2 号发，间隔就几毫秒，看着就是一起动。

## 关键代码

```python
def checksum(body):
    return (~sum(body)) & 0xFF

def write_position(sid, pos):
    high, low = (pos >> 8) & 0xFF, pos & 0xFF
    body = [sid, 5, 3, 0x2A, high, low]   # 0x2A 是目标位置
    ser.write(bytes([0xFF, 0xFF, *body, checksum(body)]))
```

主循环读两个 0~1 的数，各自换算成位置，分别发给两个舵机，退出时关扭矩。

## 过程中踩的坑

- VS Code 报 `Import "serial" could not be resolved`：编辑器选的 Python 解释器没装 pyserial，切到 lerobot 那个 conda 环境就好了。
- 报 `could not open port '/dev/cu.usbmodemXXXX'`：代码里还是 Mac 的占位端口，而且我改完没保存，跑的还是旧文件，改成 COM3 保存就好。
- 报 `could not open port 'COM3'`：驱动板没插好，或者重新插拔后串口号变了，去设备管理器确认。
- 位置 400 拆成 `01 90`：一开始没转过弯来，两个字节是大端，高字节在前。

## 小结

手写一遍串口之后，才真正知道电脑给舵机发的到底是哪几个字节——编号、地址、大小端、校验和，错一个都不动。后面用 lerobot 这些都被包成 `bus.write("Goal_Position", ...)`，但底层发出去的还是这套东西。
